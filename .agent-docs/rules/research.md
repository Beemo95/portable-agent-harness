# Research and external evidence

Use for engine APIs, addons, shader recipes, performance claims, licensing, platform policies, or competing game techniques.

1. State the question and the project Godot version/platform. Determine what fact could change the implementation decision.
2. Prefer official Godot version-matched docs and original repository/release notes; inspect actual sources or implementation before declaring a tool compatible. Distinguish stable docs from latest/unstable docs.
3. For candidate open source check: repository, release/version/date, license, installation burden, supported Godot version, maintenance signals and specific feature evidence. Never infer license or commercial rights from "free".
4. Compare 2+ approaches only when useful; include an implementable recommendation and trade-offs. If nothing is verified, label it unverified.
5. Save durable findings to `.agent-docs/research/YYYY-MM-DD-topic.md` with URLs, access date, tested/untested status and decision relevance. Do not dump unfiltered search snippets into permanent docs.
6. Promote an approved architectural decision to `.agent-docs/decisions/`; keep research and decision distinct. Revalidate time-sensitive links before relying on them again.

**Evidence:** claim, direct source, observed/tested result, environment/version, confidence/unknown. User-supplied references are primary evidence for that request; inspect them before summarizing.
